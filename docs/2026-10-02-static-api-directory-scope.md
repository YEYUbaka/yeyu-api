# Yeyu API 静态 API 收集目录范围

状态：当前有效范围。本文 supersede 之前把项目设计成自营 API 服务平台的动态方案；旧方案文件保留为历史记录，不再作为当前实施依据。

## 1. 一句话定义

`api.yeyubaka.top` 首期只是一个面向学生和个人开发者的免费 API 资料目录：收集 API 信息，帮助用户搜索、比较并跳转到官方来源和文档。

它不是 API 网关，不是第三方接口代理，也不是需要登录后才能调用的 API 服务。

## 2. 当前必须包含

- 首页搜索和分类筛选；
- API 卡片：名称、用途、分类、来源、官方文档、鉴权要求、免费额度说明、条款/许可提示、最近核验时间；
- 资料状态：来源已核验、待核验、仅官方链接等；
- 明确提示第三方服务条款和免费额度会变化，调用前必须回到官方页面核验；
- 桌面端和移动端可读布局；
- 只读的静态站点构建产物和可回滚发布包。

## 3. 当前明确不做

- FastAPI 运行时、PostgreSQL、Redis、Docker Compose；
- 邮箱注册、GitHub OAuth、登录、用户中心、后台管理；
- API Key 创建、调用、计费、每日额度、限流、审计；
- 在线调试、API 转发、缓存上游响应、stale fallback；
- 任意 URL 代理、开放抓取、用户投稿；
- 虚构调用量、延迟、健康状态或免费额度；
- 将第三方 API 的响应包装成 Yeyu API。

仓库中已有动态平台代码和历史设计文档不删除、不伪装成已上线能力；后续任务不得继续扩大这些代码的范围。

## 4. 目录数据最低字段

每条资料必须记录：

| 字段 | 约束 |
| --- | --- |
| 名称/分类/简介 | 只写可由来源支持的事实 |
| 来源与官方文档 | 固定 HTTPS 官方链接，不接受用户运行时输入 |
| 鉴权要求 | 无需 Key、可选、必需或待核验 |
| 免费额度 | 原文摘要 + 核验日期，不把“免费”写成“无限” |
| 许可/再分发 | 记录代码、数据、托管 API 三者的区别；未确认则仅资料/仅链接 |
| 稳定性与维护状态 | 只记录有证据的状态，否则标记待核验 |
| 更新/核验时间 | 使用日期，提醒用户重新阅读官方条款 |

不记录 API Key、Token、Cookie、密码、私钥或任何真实凭据。

## 5. 视觉方向

页面可以沿用 `blog.yeyubaka.top` 的视觉语言，但只借鉴通用设计，不复制个人内容或旧站资源：

- 半透明浅色顶部导航；
- 宽幅但克制的 API 目录 Banner；
- `#01C4B6` 青绿色、灰蓝正文、白色圆角卡片和柔和阴影；
- 桌面端“侧栏分类 + API 卡片网格”，移动端单列；
- 搜索优先，不使用 SaaS 式虚假统计和营销数字；
- API 路径、鉴权和版本等技术信息使用等宽字体。

## 6. 发布边界

本地只生成静态构建和压缩包。未来如发布，只新增独立的 `api.yeyubaka.top` 静态 root/vhost；DNS、证书、Nginx、服务器账号和权限变更仍需单独说明影响、验证方式和回滚方案，并等待确认。

不得覆盖 `E:\AI_projects\yeyubakahome_Web`、`/www/wwwroot/yeyubaka.top`、`new.api.yeyubaka.top` 或任何既有服务。
